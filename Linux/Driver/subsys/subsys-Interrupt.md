# 中断子系统
## 中断上下半部
主要目的：实现中断处理函数的快进快出，**那些对时间敏感、执行速度快的操作可以放到中断处理函数中，即上半部**；剩下的所有工作都可以放到下半部去执行。

- 参考设置
  - 如果要处理的内容不希望被其他中断打断，那么可以放到上半部；
  - 如果要处理的任务对时间敏感，可以放到上半部；
  - 如果要处理的任务与硬件有关，可以放到上半部；
  - 除了上述三点以外的其他任务，优先考虑放到下半部；

### 上半部
    即中断处理函数

### 下半部
下半部机制有如下几种，`Bottom half, BH` 已被废弃，主要使用软中断和 `tasklet`：
1. 软中断
   - `softirq_action` 结构体 + `softirq_action softirq_vec[NR_SOFTRQS](全局数组)`；
   - 通过 `open_softirq` 向上述数组中注册中断处理函数，中断发生时从数组中取出对应的处理函数并执行；
   - 通过 `raise_softirq` 触发处理；
   - 软中断必须在编译的时候静态注册；
2. tasklet
   - 通过 `task_init` 或者 `DECLARE_TASKLET` 宏进行初始化；
   - 在上半部中通过 `task_schedule` 注册需要在下半部中进行处理的 `tasklet`；
3. 工作队列
   - 工作队列在进程上下文执行，将要推后的工作流交给一个**内核线程**去执行；
   - 工作队列允许睡眠或重新调度；

## 设备树中的中断
### 设备树中的中断描述
- `#interrupt-cells`：指定中断源的信息 `cells` 个数；
- `interrupt-controller`：表示当前节点为中断控制器（不是只有 `GIC` 才是中断控制器）；
- `interrupts`：指定中断号（可从芯片手册上查找），触发方式等（更具 `#interrupt-cells` 指定信息）；
- `interrupt-parents`：指定中断控制器（表示当前中断被该控制器控制）；

### 在代码中获取设备树中的中断信息
1. `irq_of_parse_and_map`
2. `gpio_to_irq`

## 使用
1. 中断里面可以使用自旋锁，但是使用之前（在获取锁之前）一定要先禁止本地中断（本 cpu 中断），否则可能导致死锁的发生。
