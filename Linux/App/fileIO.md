# 文件 IO 基础
文件 I/O 指的是对文件的输入/输出操作，即文件的读写操作，而 Linux 下一切皆文件。

## 文件管理
### 静态文件与 inode
- 文件在没有被打开的情况下一般都是存放在磁盘中，文件存放在磁盘文件系统中，并且以一种固定的形式存放，我们把他们称为静态文件。

- 硬盘的最小存储单位叫做扇区（sector，512 字节），操作系统读取硬盘时一次性读取一个块（block，常为 4KB，即 8 个扇区）。

- **在对磁盘进行分区、格式化时会将其分为两个区域：一个数据区，用于存储文件中的数据；另一个是 inode 区，用于存放 inode table**。
  - 不同的 inode 表示不同的文件，**每个文件都必须对应一个 inode**；
  - 每个 inode 都有一个与之对应的数字编号，通过该编号找到 inode table 中对应的 inode。可以通过 `ls -i` 查看文件的 **inode 编号**，也可以通过 `stat file_name` 来查看；
  - **inode 结构体**记录了文件的大小、所有者、权限、时间戳、数据存储块地址等信息，但是文件名并不记录在 inode 中；

- 打开一个文件，系统内部的过程：
  1. 系统找到这个文件名所对应的 inode 编号；
  2. 通过 inode 编号从 inode table 中找到对应 inode 结构体；
  3. 根据 inode 结构体中记录的信息，确定文件数据所在的 block，并读出数据。

### 文件打开时的状态
- 调用 open 函数打开文件后，**内核会申请一段内存（一段缓冲区）**，并且将静态文件的数据内容从存储设置中读取到内存中进行管理、缓存（也把内核中的这份文件数据叫做**动态文件、内核缓冲区**）。以后对该文件的读写操作都是针对内存中的这份动态文件进行的。

- 对动态文件进行读写后，需要同步操作来实现与静态文件的**同步**，这是通过内核来完成的。内核会将动态文件更新（同步）到磁盘设备中。

- **块设备**硬件本身有读写限制等特征，通过以块为单位（包含多个扇区）进行读写；**内存**可以按字节为单位进行操作，同时可以随机访问任意地址。灵活性更高，效率（读写速度差异）也提高了。

- Linux 系统中，通过 `struct task_struct` 表示进程控制块（Process Control Block, PCB），用于管理进程，如记录进程的状态信息、运行特征等。

## 文件描述符
- 对于 Linux 内核而言，所有打开的文件都会通过文件描述符进行索引。
  - `open()` 函数会返回文件描述符；
  - `socket()` 函数会返回文件描述符；

- **所有执行 I/O 操作的系统调用都是通过文件描述符来索引到对应的文件**。

## 空洞文件
- 使用 lseek 可以修改文件的当前读写位置偏移量，允许文件偏移量超出文件长度。

- 由于 lseek 修改偏移量后导致文件中出现部分区域没有写入任何数据，这部分区域就被称为文件空洞，相应的文件也被称为空洞文件。

- 文件空洞部分实际上并不会占用任何物理空间，直到在某个时刻对空洞部分进行写入数据时才会为它分配对应的空间。但是空洞文件形成时，逻辑上该文件的大小是包含了空洞部分的大小的，这点需要注意（ls 命令查看文件大小为 8K，但是使用 du 命令查看磁盘占用是 4K）。

- 空洞文件对多线程共同操作文件是极其有用的。创建一个很大的文件，可以将文件分为多段，然后使用多线程来操作，每个线程负责其中一段数据的写入。
  - 在使用迅雷下载文件时，还未下载完成，就发现该文件已经占据了全部文件大小的空间。
  - 在创建虚拟机时，给虚拟机分配了 100G 的磁盘空间，但其实系统安装完成之后，开始也不过只用了 3、4G 的磁盘空间。

## 多次打开同一个文件
- 一个进程内多次 open 打开同一个文件，那么会得到多个不同的文件描述符，在关闭文件的时候也需要调用 close 关闭各个文件描述符；

- 一个进程内多次 open 打开同一个文件，在内存中并不会存在多份动态文件；

- 多个不同的进程中调用 open 打开磁盘中的同一个文件，同样在内存中也只是维护了一份动态文件。多个进程间共享，它们有各自独立的文件读写位置偏移量；

- 一个进程多次 open 打开同一个文件，不同文件描述符所对应的读写位置偏移量是相互独立的；
  - [ ] open 打开同一个文件，是创建了新的 struct file 结构体，而不是创建一个 struct file*，指向同一个 struct file？

- 动态文件的关闭：当文件的引用计数为 0 时，系统会自动将其关闭。同一个文件被打开多次，文件表中会记录该文件的引用计数。

- 多次打开同一文件进行写操作与 O_APPEND 标志
  在程序中多次打开同一文件，并对其进行写操作（不是并发/并行写）。
  - 如果没有添加 O_APPEND 标志，则写操作会有覆盖，只有最后一次的写操作是有效的；
  - 如果添加了 O_APPEND 标志，则多个写操作的结果是合并；

## 复制文件描述符
- 复制得到的文件描述符和原始文件描述符都可以对文件进行 I/O 操作，它们具有相同的权限。

- 复制得到的文件描述符与原始文件描述符都指向同一个文件表（struct file，只是新建了 struct file*，它们都指向同一个 struct file）。

- 同样需要使用 close 来关闭文件描述符。

- 通过 dup 复制文件描述符
  ```c
  #include <unistd.h>

  int dup(int oldfd);
  ```
  - 成功时返回一个新的文件描述符，由操作系统分配，分配原则遵循文件描述符分配原则；如果失败返回 -1，同时设置 errno 值。

- 通过 dup2 复制文件描述符
  ```c
  #include <unistd.h>

  int dup2(int oldfd, int newfd);
  ```
  - dup 由系统分配文件描述符，dup2 可以手动指定文件描述符。
  - 成功时返回 newfd，失败时返回 -1，并设置 errno。

## 文件共享
- 文件共享指的是同一个文件（同一个 inode）被多个独立的读写体同时进行 I/O 操作。
  - 多个独立的读写体可以理解为对应于同一个文件的多个不同的文件描述符；
  - 同时进行 I/O 操作指的是一个读写体操作文件尚未调用 close 关闭的情况下，另一个读写体去操作文件。

- 文件共享的意义有很多，多用于多进程和多线程编程环境中，以减少 I/O 时间、提升效率。

- 文件共享的核心是：如何创建多个不同的文件描述符来指向同一个文件。
  - 多次调用 open 打开同一个文件；
  - 使用 dup 或 dup2 函数对文件描述符进行复制；

## 原子操作与竞争冒险
- O_APPEND 实现原子操作
  - 当 open 函数的 flags 参数中包含了 O_APPEND 标志，每次执行 write 写入操作时都会将文件当前写位置偏移量移动到文件末尾，然后再写入数据。
  - 这里的 “移动当前写位置偏移量到文件末尾、写入数据” 这两个操作组成了一个原子操作。
  - 加入 O_APPEND 标志后，不管怎么写入数据都会是从文件末尾写。
- pread() 和 pwrite()
  - 系统调用；
  - 与 read() 和 write() 的区别是 pread() 和 pwrite() 可用于实现原子操作；
  - 参数中指定位置偏移量 offset，调用这两个函数相当于先调用 lseek 后再调用 read/write，这两步操作组成一个原子操作。
  - 它们不更新文件表中的当前位置偏移量。
- 创建文件
  - 通过给 open 函数添加 O_EXCL | O_CREATE 标志，将 “判断文件是否存在、创建文件” 这两个步骤合并为一个原子操作，避免同一个文件被创建多次。

## 截断文件
使用系统调用 truncate() 或 ftruncate() 可将普通文件截断为指定字节长度。
```c
#include <unistd.h>
#include <sys/types.h>

int truncate(const char *path, off_t length);   // 使用路径来指定文件
int ftruncate(int fd, off_t length);            // 使用文件描述符来指定文件
```
  - 如果当前文件的大小大于参数 length 所指定的大小，则多余的数据将被丢弃；
  - 如果当前文件的大小小于 length，则将其进行扩展，对扩展部分进行读取将得到空字节“\0”；
  - 使用 ftruncate 之前需调用 open 函数打开文件，且必须有写权限；
  - 调用上述两个函数不会导致文件读写位置偏移量发生改变，所以截断之后一般需要重新设置文件当前的读写位置偏移量。

## 返回错误处理与 errno
- 在 Linux 系统中对常见的错误做了一个编号，每一个编号都代表着一种不同的错误类型。当函数执行发生错误时，操作系统会将这个错误所对应的编号赋值给 errno 变量。

- 每一个进程（程序）都维护了自己的 errno 变量，它是程序中的全局变量，该变量用于存储就近发生的函数执行错误编号，同时它会被最新一次的错误码覆盖。

- errno 本质上是一个 int 类型的变量，需要注意的是，并不是执行所有的系统调用或 C 库函数出错时操作系统都会设置 errno。这一点可以通过 man 手册查看相应函数说明进行确认。

- errno 的获取和使用
  - 通过包含 <errno.h> 头文件即可获取 errno 的值；
  - 通过 strerrno 将 errno 转换为对应的字符串类型的错误信息，需要包含 <string.h> 头文件；
  - 通过 perror 函数打印 errno 对应的错误信息，包含 <stdio.h> 头文件；

## 退出函数
- 一般原则，程序执行正常退出 return 0，而执行函数出错退出 return -1；

- 在 Linux 系统中，进程（程序）退出可以分为正常退出和异常退出；

- 在 Linux 系统中，进程正常退出除了可以使用 return 之外，还可以使用 exit()、_exit() 和 _Exit()；

- _exit()
  - Linux 系统调用；
  - main 函数中使用 return 后返回，return 执行后把控制权交给调用函数，结束该进程；
  - 调用 _exit() 函数会清除其使用的内存空间，并销毁其在内核中的各种数据结构，关闭进程的所有文件描述符，并结束进程、将控制权交给操作系统：
    ```c
    #include <unistd.h>

    // status-状态标志，0-正常结束，其他值表示程序执行过程中监测到有错误发生
    void _exit(int status);
    ```

- _Exit()
  - Linux 系统调用；
  - _exit() 和 _Exit() 两者等价，用法作用一样：
    ```c
    #include <stdlib.h>

    void _Exit(int status);
    ```

- exit()
  - 标准 C 库函数；
  - exit() 会先执行一些清理工作，最后调用 _exit() 函数；
    ```c
    #include <stdlib.h>

    void exit(int status);
    ```

# 标准 I/O 
标准 I/O 库是标准 C 库中用于文件 I/O 操作相关的一系列库函数集合，通常在头文件 <stdio.h> 中声明。

标准 I/O 对文件 I/O 进行了封装，在文件 I/O 的基础上增加了很多细节，例如分配 stdio 缓冲区、以优化的块长度执行 I/O 等。这些处理使用户不必担心如何选择使用正确的块长度。

- 标准 I/O 和文件 I/O 的区别：
  - 标准 I/O 是标准 C 库函数，而文件 I/O 则是 Linux 系统调用；
  - 标准 I/O 是由文件 I/O 封装而来，标准 I/O 内部实际上是调用文件 I/O 来完成实际操作的；
  - 标准 I/O 具有更好的移植性，因为它屏蔽了不同操作系统的系统调用 API；
  - 标准 I/O 在性能和效率上更具优势，标准 I/O 库在用户空间维护了自己的 stdio 缓冲区，而文件 I/O 在用户空间是不带有缓冲的；
  - 标准 I/O 的操作是围绕 FILE 指针进行的，而文件 I/O 是围绕文件描述符进行的。
